# Agent Note: The interactive whiteboard — Excalidraw editor over the diagram card

Status: implemented

English | [中文](2026-09-01-interactive-whiteboard-excalidraw.zh.md)

## Problem

Phase one produced read-only diagram cards: the model draws, the user looks. The obvious next step is a real canvas — the user edits the produced `.excalidraw` file and saves it back, closing the loop the file contract already opened. The client bundle pipeline had no precedent for embedding a heavy third-party editor, and cross-scope shared state for the overlay was unproven.

## Decision

Add `packages/client/ui-diagram-canvas`: a full-screen Excalidraw editor overlay registered in the `shell.overlay` list seat, opened from the diagram card's new `diagram.card.open` action chain, backed by a Host Remote gateway (`diagram.save` / `diagram.read` on `@deepseek-ai/dsh-diagram`) that writes through the session `fs` seam.

### Embedding the editor: one publishable artifact

`@excalidraw/excalidraw@0.18` lazily imports its diagram libraries; rolldown splits those into hash-named chunks the module loader cannot serve and the `files` list cannot publish. `tsdown` 0.22 does not forward the `inlineDynamicImports` output option, so the `clientBundle` preset gained `ClientBundleOptions.client` (object-form `outputOptions` merged into the preset's, caller `plugins` extending the pipeline) and the canvas package pins every dynamic import plus dagre-d3-es's one runtime `import()` back into its graphlib module into the single `lib/client.js`. The artifact is ~12 MB raw / ~3 MB gzip — a real startup cost, recorded as a Known Limitation.

### One canvas instance across two scopes

A store handle cannot mount in two scopes (`shell.overlay` is root, the card chain is session), so the panel and the open action share one engine **instance** (`createCanvasStore().create()`) passed through the registrations' inject faces — the PopupSelectView precedent, not a second store.

### The Host gateway

`DiagramRemote` (`TypertRemoteService`, `@Remote('save')` / `@Remote('read')`) lives on the host plane (a `dsh-diagram/host` entry in the web composition) because the Gateway resolves services from the root scope, while the tool plugin stays in agent presets. Typert artifacts (`./typert`, `./remote`) are generated by the workspace typert plugin at build; `typert-loader` auto-registers the descriptors; the client assembly (`api/remotes`) mounts the `diagram` namespace.

### No session event yet

Canvas saves are not recorded on the session log. The model-visible ⟺ logged rule binds when content enters a model request; that happens in the model-read milestone (M-C), which will add the event in the same change.

## Why no cordis-catalog entry / no `@mode`

Not applicable — the gateway is a Remote service, not a typed session event.

## Alternatives considered

**Let the card bundle import the editor directly.** Rejected: 12 MB would land in every session's startup for a feature most sessions never open; the separate panel package keeps the card bundle lean and the editor behind a distinct artifact.

**`dsh.client.external` module-table row for the editor.** Rejected: the module-graph rules reserve external rows for infrastructure/transport; a feature bundle carrying the editor privately (inlined) is the sanctioned shape, and `inlineDynamicImports` keeps that bundle publishable.

**Share state through a second store synced by hand.** Rejected: two sources of truth; the shared instance through inject faces is the existing pattern and keeps one authoritative state.

**Host the save/read on the tool plugin.** Rejected: the tool mounts per-preset in an isolated realm the Gateway cannot resolve; the host-plane entry is required.

## Consequences

Startup downloads grow by ~3 MB gzip for every Web session (Known Limitation, with the deferred option of splitting the editor into a lazily delivered row).

The `diagram` card gains an open-action chain; the card package stays free of any panel dependency, and compositions without the canvas package simply render no open action.

The web composition now mounts `dsh-diagram/host`, whose typert descriptors are registered by `typert-loader` like every other Remote contributor; the `api/remotes` client assembly mounts the `diagram` namespace.

Canvas saves bypass the session log until M-C; any milestone that lets saved content reach a model request must add the corresponding session event in the same change.

## Verification

- `ui-diagram-canvas`: 20 tests, per-file 100% coverage — store actions, open-action select/mount, panel states (pending/dirty/save success/failure/untitled), registration + HMR removal, and the save bridge against a fake `remote.diagram`.
- `dsh-diagram`: 35 tests, per-file 100% coverage including the Remote gateway (save/read round trip, path policy, write/read failures, oversized reads).
- The bundle stays one `lib/client.js` with no runtime dynamic imports (the one remaining `import(...)` is inside a JSDoc comment).
